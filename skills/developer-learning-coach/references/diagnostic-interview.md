# Diagnostic interview

Use this reference only for the assessment phase. The instrument is a
structured coaching interview, not a validated psychological test. Do not
calculate a pseudo-precise total score.

## Construction rules

- Ask 15-20 numbered questions; 18-19 is a useful default.
- Prefer examples from the user's work-context card. If none exists, ask for
  their domain and one current learning target before presenting scenarios.
- Ask about the most recent 1-3 months where possible. Specific episodes are
  stronger evidence than general identity statements.
- Keep matrix questions compact. A matrix may contain several ratings, but do
  not hide an exhausting multi-page survey inside one number.
- Provide a response template for any question with more than three fields.
- Include at least two questions that request a concrete past episode.
- Do not interpret answers until the user has replied.

## Default 19-question blueprint

Adapt wording and examples, but retain the coverage.

1. **Context, short answer.** What kind of development work do you do, what
   technical topic are you trying to learn now, and what would you be able to
   do if learning succeeded?

2. **Starting behavior, choose up to three and rank the top two.** In a free
   hour reserved for learning, what usually happens: cannot choose a first
   step; postpone; feel no desire; start and lose interest; start normally;
   feel anxiety or irritation at expected difficulty; do something easier;
   another concrete behavior?

3. **Initiation ratings, 0-10.** Rate difficulty starting when the topic is:
   intrinsically interesting; useful for work but dull; part of a required
   course; self-chosen. Anchor 0 = start immediately, 10 = almost never start.

4. **Interest comparison, situational.** Give one recent example where strong
   interest did and one where it did not carry you through difficulty. What
   happened at the first serious obstacle?

5. **Reaction to not understanding, rank the first three reactions.** Seek a
   different explanation; form and test a hypothesis; experiment for a long
   time; feel curious; feel irritated; doubt competence; seek a hint; open a
   complete solution; postpone; switch topics; ask a person or AI.

6. **Failure tolerance, 0-10 plus example.** How willing are you to make several
   visible mistakes while learning? Anchor 0 = avoid them, 10 = treat them as
   normal evidence. Ask what happened after the last failed attempt.

7. **Ambiguity matrix, 0-10.** How hard is it to start when you do not know:
   whether success is possible; how long it will take; where to search; what
   counts as done? Anchor 0 = no problem, 10 = blocks starting.

8. **Closed versus open task.** Compare a bounded assignment with explicit
   steps to an investigation of unfamiliar code or behavior with no known
   algorithm. Which do you start first, which teaches you more, and where does
   each become unpleasant?

9. **Competence and challenge, choose and explain.** Learning feels best when:
   almost everything works; 70-80% works; about half works; tasks are at the
   edge of current ability. Ask how long motivation survives after repeated
   failure.

10. **Domain scenarios, ranking.** Generate 5-7 short scenarios from the user's
    actual domain: one conceptual topic, one unfamiliar-code reading task, one
    debugging task, one implementation without a recipe, one new tool or
    library, and optionally one routine skill. Rank from easiest to start to
    hardest, then identify which would be most satisfying to finish.

11. **Learning formats, rank top five and bottom three.** Reading; video;
    instructor explanation; AI dialogue; worked example; copying and modifying
    an example; independent problem; project; teaching someone; drills;
    debugging; reading production code. Ask what action the learner performs in
    the effective formats. Do not infer a sensory learning style.

12. **Conceptual versus procedural, choose a sequence.** A: model first, then
    steps; B: steps first, then model; C: strict process structure with deep
    explanation inside it; D: explore first, formalize later. Ask for a recent
    case where the preferred sequence helped or failed.

13. **Guidance and fading.** For a new skill, choose a starting point: fully
    worked solution; partially completed solution with hints; similar example
    plus independent task; independent task immediately. What evidence tells
    you that a hint or example can be removed?

14. **Retention matrix, 0-10.** After one week, how much can you explain or
    reproduce without materials after: an article; a lecture; solved exercises;
    a project; explaining in your own words? Anchor 0 = almost nothing, 10 = can
    retrieve and apply. Ask for evidence rather than confidence where possible.

15. **Consolidation behavior, frequency.** Never/occasionally/usually for:
    retrieval without notes; spaced review; re-solving; explaining without
    materials; mixed practice; rereading or rewatching. Ask what prevents the
    strongest omitted behavior.

16. **Courses and external structure.** What happens with: a course with a
    deadline; the same course without one; a progress bar; a certificate; a
    project needed at work? Ask whether structure creates useful action or only
    pressure to reach the end.

17. **Planning loop, frequency plus episode.** Does this occur: ambitious plan
    -> enthusiasm -> missed sessions -> backlog -> avoidance -> abandonment ->
    new plan? Ask for the latest example and the first point where recovery was
    still easy.

18. **What counts as learning.** If 40 minutes of reading unfamiliar code,
    documentation, and hypothesis testing produces one new understanding, does
    that count as a successful session? Contrast it with course completion,
    notes, and solved exercises. Ask what visible artifact is needed, if any.

19. **Motivation and successful episodes.** Choose and rank 3-5 drivers:
    curiosity; career growth; money; competence; visible progress; deadline;
    evaluation; competition; making a product; work application; understanding
    difficult things; course completion; certificate. Then describe 2-3 genuine
    successful learning episodes using: prior competence, structure, teacher,
    deadline, feedback speed, repetition, permission to err, and clarity of the
    next step. Finish with realistic weekly time and the smallest session that
    still feels worthwhile.

## Follow-up decision rule

Ask 3-7 follow-ups only if one of these remains unresolved:

- stated preference conflicts with a concrete success or failure episode;
- high interest coexists with repeated failure to start;
- the role of competence, ambiguity, or visible evaluation is unclear;
- passive formats are preferred but retention evidence is weak or absent;
- the learner reports structure as both helpful and demotivating;
- the proposed plan would exceed actual time or work constraints;
- there is no evidence about retention, transfer, or independent performance.

State the gap, ask the smallest question that resolves it, and wait.
