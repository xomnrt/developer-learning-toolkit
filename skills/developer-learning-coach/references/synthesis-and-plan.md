# Synthesis and plan contract

Use this reference after the diagnostic interview and any necessary follow-up.
The final response should be useful without exposing hidden chain-of-thought.
Show evidence, concise rationale, confidence, and actionable consequences.

## 1. Working causal model

Analyze this sequence:

`motivation -> initiation -> difficulty appraisal -> practice -> consolidation -> continuation`

For every stage report:

1. what works;
2. the bottleneck;
3. the most plausible mechanism;
4. how it appears in reported behavior;
5. the design response;
6. confidence: high, medium, or low, with the missing evidence when low.

Do not imply that the sequence is strictly linear. Identify feedback loops such
as failure reducing perceived competence, avoidance reducing practice, and
reduced practice making the next attempt harder.

Separately evaluate, using evidence from answers:

- dependence of motivation on perceived competence;
- ambiguity tolerance;
- failure tolerance;
- need for external structure;
- need for scaffolding and rate of fading;
- passive-consumption tendency;
- use of learning to confirm existing competence;
- ability to explore open-ended problems;
- curiosity versus disciplined continuation;
- likelihood of selecting tasks far above current skill.

## 2. Profile scales

Place the learner approximately on 0-10 continua. Define both anchors and cite
the relevant answers. Include only dimensions supported by evidence:

- structured <-> exploratory;
- conceptual <-> procedural;
- example-first <-> problem-first;
- guided <-> independent;
- mastery-oriented <-> novelty-oriented;
- low <-> high ambiguity tolerance;
- low <-> high failure tolerance;
- external <-> internal structure;
- fast <-> delayed feedback;
- repetition <-> novelty;
- concrete <-> abstract.

The numbers are communication aids, not measurements. Explain what each
position changes in real study design and where the estimate is uncertain.

## 3. Personalized learning loop

Derive, rather than assume, a session loop. It may contain:

`orientation -> prior retrieval -> one concept -> worked example -> guided
practice -> independent attempt -> feedback -> retrieval -> next review`

Set initial values for:

- session length and minimum viable session;
- amount of new material;
- ratio of familiar, challenging, and transfer tasks;
- initial solo-attempt time before a hint;
- hint ladder and conditions for viewing a full solution;
- how and when scaffolding fades;
- review schedule;
- observable mastery checks.

For every numeric setting, give a reason from the answers or label it a
1-2-week experiment with an adjustment rule.

## 4. Difficulty ladder

Create 5-8 levels appropriate to the target skill. Use observable performance,
not feelings alone. A useful generic progression is:

1. recognize and explain the vocabulary with support;
2. trace a worked example and explain why each step exists;
3. complete a partially worked example;
4. solve a close analogue with a hint;
5. solve a standard task independently;
6. debug or explain a variant;
7. transfer the principle to a new context;
8. teach, review, or design a solution and justify tradeoffs.

Define evidence required to advance and when to step down temporarily. Do not
force all eight levels if the target skill needs fewer.

## 5. Stuck protocol

Adapt a bounded protocol that prevents both instant solution viewing and
unproductive persistence:

1. restate the goal and done condition;
2. list known facts, observed output, and constraints;
3. name the smallest specific unknown;
4. form one testable hypothesis;
5. run the cheapest discriminating test for a bounded interval;
6. record what changed;
7. request the smallest useful hint;
8. retry before escalating the hint;
9. view a complete solution only after explicit conditions are met;
10. close it, reproduce the reasoning independently, and solve a variation.

Set the timebox from the learner's answers and task feedback speed. Progress is
new evidence or a reduced search space, not merely elapsed time. If two cycles
produce neither, change strategy or lower the task level.

## 6. Resilient planning system

Design a 4-8-week rolling system around the learner's real work and available
time:

- 1-2-week cycles with a single capability outcome;
- realistic sessions per week plus an optional bonus session;
- minimum viable session;
- a rule for selecting the next topic;
- deadline use only if it improves action without turning completion into the
  goal;
- optional weekly retrieval or transfer check;
- a compact tracker of mastery evidence;
- restart at the next scheduled session after interruptions, with no backlog.

Include one representative week using domain-relevant tasks. If no domain
context exists, keep the example generic and label it for replacement.

## 7. Metrics

Separate activity indicators from mastery evidence.

Activity may include time, pages, lectures, or tasks attempted. It describes
exposure, not learning.

Use a simple mastery scale such as:

0. not yet recognized;
1. recognize with materials;
2. explain or trace with support;
3. perform a standard task with hints;
4. perform independently and debug errors;
5. transfer, compare alternatives, and explain to another developer.

Require concrete evidence for a level and allow different subskills to have
different levels.

## 8. Required closing summary

End with all of the following, merging sections when repetition would add no
value:

1. concise assessment of the current learning system;
2. 3-5 main causes of difficulty or motivation loss;
3. profile scales;
4. one-session model;
5. 4-8-week system;
6. difficulty ladder;
7. stuck protocol;
8. material-selection rules;
9. task-difficulty rules;
10. practices to avoid;
11. productive-struggle versus too-hard criteria;
12. progression toward independence and ambiguity tolerance;
13. one representative week.

Also state the strongest unknowns and how the learner can test the model in
practice. Avoid repeating the same recommendation under several headings.
