# Developer Learning Toolkit

[English](README.md) | [Русский](README.ru.md)

Обучение часто ломается где-то между мотивацией, неопределённостью, сложностью
задачи, практикой и обратной связью. Обычный учебный план не показывает, на
каком именно участке возникла проблема.

Developer Learning Toolkit описывает рабочий контекст и карьерные цели,
анализирует текущую систему обучения и строит подробный путь к технологии,
набору обязанностей или новой технической специальности.

Набор предназначен для разработчиков любого направления и технологического
стека.

## Что входит в набор

| Skill | Назначение |
| --- | --- |
| [`developer-work-context`](skills/developer-work-context/) | Собирает информацию о текущей работе, используемых ранее и планируемых технологиях. Создаёт переиспользуемую карточку рабочего контекста. |
| [`developer-learning-coach`](skills/developer-learning-coach/) | Диагностирует текущую систему обучения и создаёт персональную модель практики, повторения, планирования и управления сложностью. |
| [`developer-learning-roadmap`](skills/developer-learning-roadmap/) | Строит подробный roadmap для технологии, нового уровня ответственности или перехода в другую техническую область. |
| [`developer-mock-interview`](skills/developer-mock-interview/) | Проводит адаптивные мок-собеседования по завершённым разделам roadmap и целевой роли. |

Skills можно использовать независимо, но вместе они дают более точный
результат.

## Как устроен полный процесс

```text
Опрос о работе, технологиях и карьерных направлениях
        ↓
Developer Work Context Card
        ├── Диагностика обучения
        │        ↓
        │   Модель обучения, структура занятия, difficulty ladder,
        │   stuck protocol и метрики mastery
        │
        └── Карта разрыва между текущим и целевым состоянием
                 ↓
            Подробный roadmap для технологии, уровня или перехода
                 ↓
            Циклы по 1–2 недели с проверками mastery
                 ↓
            Интерактивный граф зависимостей и экспорт прогресса
                 ↓
            Мок-собеседования по завершённым capabilities
```

Toolkit не строит профиль заранее. Первый диагностический этап заканчивается
вопросами и ждёт ответов пользователя.

## Установка

Репозиторий упакован как plugin для Codex и Claude Code. Обе платформы используют
один каталог `skills/`. В плагине нет MCP-сервера, hooks, внешних аккаунтов,
analytics и сторонних runtime-зависимостей. Локальный HTML-рендерер работает на
Python standard library.

### Codex

После публичной публикации откройте `/plugins`, найдите
`Developer Learning Toolkit` и нажмите **Install**. После первой установки
начните новый диалог.

До публикации можно установить skills для текущего пользователя:

```bash
mkdir -p ~/.codex/skills
cp -R skills/developer-work-context skills/developer-learning-coach \
  skills/developer-learning-roadmap skills/developer-mock-interview \
  ~/.codex/skills/
```

Для одного проекта скопируйте их в `.codex/skills` этого проекта:

```bash
mkdir -p /path/to/project/.codex/skills
cp -R skills/developer-work-context skills/developer-learning-coach \
  skills/developer-learning-roadmap skills/developer-mock-interview \
  /path/to/project/.codex/skills/
```

Подробнее об активации skills рассказано в
[официальной документации OpenAI](https://developers.openai.com/plugins/concepts/skills).

### Claude Code через marketplace

В Claude Code 2.1.275 или новее плагин можно установить из опубликованного
GitHub-репозитория одной командой:

```text
/plugin install developer-learning-toolkit --marketplace xomnrt/developer-learning-toolkit
```

Эквивалентные shell-команды сначала регистрируют marketplace, затем устанавливают
плагин:

```bash
claude plugin marketplace add xomnrt/developer-learning-toolkit
claude plugin install \
  developer-learning-toolkit@developer-learning-toolkit-marketplace
```

Файл `.claude-plugin/marketplace.json` уже находится в репозитории. Отдельный
репозиторий для marketplace не требуется.

### Claude Code из локальной копии

Проверьте плагин и загрузите его для одного сеанса:

```bash
claude plugin validate .
claude --plugin-dir .
```

Чтобы плагин автоматически загружался в следующих локальных сеансах, клонируйте
репозиторий в пользовательский каталог Claude Code:

```bash
mkdir -p ~/.claude/skills
git clone https://github.com/xomnrt/developer-learning-toolkit.git \
  ~/.claude/skills/developer-learning-toolkit
```

Claude Code распознаёт каталог внутри `~/.claude/skills/` с файлом
`.claude-plugin/plugin.json` как пользовательский плагин. Подробности есть в
официальной документации Anthropic о
[плагинах](https://code.claude.com/docs/en/plugins/overview) и
[skills](https://code.claude.com/docs/en/skills).

### Имена для вызова

| Платформа | Рабочий контекст | Диагностика | Roadmap | Мок-собеседование |
| --- | --- | --- | --- | --- |
| Codex | `$developer-work-context` | `$developer-learning-coach` | `$developer-learning-roadmap` | `$developer-mock-interview` |
| Claude Code plugin | `/developer-learning-toolkit:developer-work-context` | `/developer-learning-toolkit:developer-learning-coach` | `/developer-learning-toolkit:developer-learning-roadmap` | `/developer-learning-toolkit:developer-mock-interview` |

Skills также могут активироваться автоматически, если запрос соответствует их
описанию.

Команды выше используют пути macOS/Linux. В другой операционной системе нужны
эквивалентные пользовательские и проектные каталоги.

## Рекомендуемый сценарий использования

В примерах ниже используются имена Codex. Для Claude Code подставьте имена из
таблицы выше.

### Шаг 1. Соберите рабочий контекст

Начните с запроса:

```text
Используй $developer-work-context. Проведи опрос на русском языке,
чтобы описать технологии, которые я использую сейчас, использовала раньше
и планирую изучать для работы.
```

Skill спросит о следующих областях:

- текущая роль и регулярные рабочие задачи;
- технологии, используемые постоянно, изредка или ранее;
- технологии, которые понадобятся в следующие 3–12 месяцев;
- задачи, выполняемые самостоятельно;
- задачи, для которых пока нужны пример или помощь;
- обратная связь, поддержка, дедлайны и доступное время;
- цели внутри текущей роли, новые технологии и возможные переходы в другую
  область;
- один проверяемый результат для ближайшего короткого цикла. Остальные цели
  сохраняются в карточке контекста.

На основании ответов будет создана `Developer Work Context Card`. В ней
фиксируются факты и цели без оценки seniority и без назначения типа обучения.

### Шаг 2. Пройдите диагностику обучения

В том же диалоге продолжите:

```text
Используй $developer-learning-coach и карточку контекста, которую мы создали.
Проводи диагностику на русском языке. Я хочу понять, почему моё обучение
останавливается, и построить устойчивую систему.
```

Сначала coach задаст примерно 15–20 вопросов. В них используются конкретные
сценарии, ранжирование, шкалы, варианты выбора и короткие описания реальных
эпизодов обучения.

Отвечайте по номерам. Коротких ответов достаточно, если вопрос прямо не просит
описать конкретный случай.

После первого раунда могут появиться 3–7 уточняющих вопросов, если осталось
важное противоречие или недостаточно данных. Опрос не должен продлеваться только
ради дополнительной информации.

### Шаг 3. Получите систему обучения

Когда данных достаточно, coach создаёт:

- причинную модель этапов: мотивация, запуск, восприятие сложности, практика,
  закрепление и продолжение обучения;
- примерный профиль по практическим параметрам;
- повторяемую структуру одного занятия;
- difficulty ladder из 5–8 уровней;
- stuck protocol, который предотвращает и мгновенный просмотр решения, и
  долгое отсутствие прогресса;
- систему на 4–8 недель без учебного долга после пропущенных дней;
- отдельные activity и mastery metrics;
- правила выбора материалов и задач подходящей сложности;
- пример недели на основании реальной работы пользователя.

Рекомендации должны быть связаны с конкретными ответами. Слабые выводы должны
обозначаться как гипотезы, а не как установленные факты.

### Шаг 4. Постройте подробный roadmap

Передайте skill карточку контекста и, если она уже есть, модель обучения:

```text
Используй $developer-learning-roadmap. Я хочу за шесть месяцев перейти из
frontend-разработки в data engineering. Построй карту разрыва между текущим и
целевым состоянием, используй roadmap.sh для проверки охвата тем, сверяй
технические сведения с первичными источниками. Нужны подробные этапы, проекты,
критерии mastery и первые две недели на уровне отдельных занятий.
```

Skill также подходит для одной технологии или роста уровня ответственности:

```text
Используй $developer-learning-roadmap и составь план роста до обязанностей
middle frontend-разработчика. Опиши этот уровень через наблюдаемые задачи и
самостоятельность. У меня есть 8 часов в неделю на протяжении 16 недель.
```

Подходящий roadmap из [roadmap.sh](https://roadmap.sh/) используется как карта
возможных тем и связей. Skill выбирает разделы, которые нужны для целевой
работы, проверяет актуальные технические сведения по первичным источникам и
складывает отложенные темы в отдельный backlog. Название уровня не считается
единым стандартом для всех компаний.

Диагностика обучения для roadmap необязательна. Она полезна, если выполнение
плана зависит от мотивации, запуска занятий, переносимости сложности или
способа повторения.

### Шаг 5. Создайте интерактивный roadmap

Попросите roadmap skill подготовить HTML:

```text
Используй $developer-learning-roadmap. Создай roadmap JSON и интерактивный HTML
с графом зависимостей. Я хочу отмечать capabilities как завершённые и сохранять
прогресс в localStorage.
```

Автономная страница содержит граф, доступное списочное представление, состояния
blocked, ready и completed, фильтры, описание практики и mastery, а также
экспорт и импорт прогресса. Она не использует CDN, analytics и сетевые запросы.

Для надёжного сохранения через браузер запустите локальный сервер:

```bash
python3 -m http.server 8000 --directory /path/to/output
```

Затем откройте `http://localhost:8000/roadmap.html`. HTML можно открыть напрямую,
но поведение `localStorage` для `file:` URL различается между браузерами.

### Шаг 6. Пройдите мок-собеседование

Передайте skill текущий roadmap или экспорт прогресса:

```text
Используй $developer-mock-interview и мой экспорт прогресса. Проведи реалистичное
мок-собеседование для Middle системного аналитика. Давай по одному практическому
кейсу, жди моего ответа, строго и конструктивно разбирай его и постепенно
увеличивай неопределённость.
```

Отметка completed не считается доказательством mastery. Skill проверяет материал
через уточнение требований, системную модель, диагностику, компромиссы и способ
проверки решения. Итоговая сводка показывает подтверждённые capabilities и узлы,
которые стоит повторить.

## Сокращённые сценарии

### Пропустить опрос о работе

Если coach уже знает роль и учебную цель:

```text
Используй $developer-learning-coach, чтобы выяснить, как мне лучше изучать
внутреннее устройство баз данных. Я backend-разработчик и хочу самостоятельно
диагностировать проблемы производительности запросов. Начни с опроса и пока не
давай рекомендаций.
```

### Передать готовое описание контекста

```text
Используй $developer-learning-coach и контекст ниже.

[Вставьте роль, технологии, ограничения и целевую способность.]
```

### Продолжить после перерыва

```text
Продолжи диагностику $developer-learning-coach на основании моих предыдущих
ответов. Сначала кратко перечисли, что уже известно, и задай только оставшиеся
важные вопросы.
```

### Проверить существующую систему

```text
Используй $developer-learning-coach, чтобы проверить этот учебный план по моему
существующему профилю. Покажи, какие предположения ещё подтверждаются, а какие
нужно проверить заново.
```

### Спланировать переход в другую специальность

```text
Используй $developer-work-context, чтобы зафиксировать мой текущий опыт и
возможный переход из mobile-разработки в backend. Затем используй
$developer-learning-roadmap: сравни переносимые навыки, недостающий фундамент,
bridge projects и реалистичную последовательность на шесть месяцев.
```

## Выбор языка

Внутренние инструкции skills написаны на английском для переносимости. Опрос и
результат формируются на языке пользователя.

Язык можно указать явно:

```text
Используй $developer-learning-coach. Проводи опрос и анализ на русском языке.
```

```text
Use $developer-learning-coach. Conduct the interview in English.
```

Если язык не указан, используется язык последнего содержательного сообщения.
Дополнительный вопрос задаётся только тогда, когда выбор действительно неясен.
Названия API, библиотек, команды и другие технические идентификаторы не
переводятся без необходимости.

## Чего toolkit не делает

Он не должен:

- классифицировать пользователя как visual, auditory или kinesthetic learner;
- диагностировать ADHD, тревожное расстройство, депрессию или другое состояние;
- делать вывод о mastery на основании стажа или количества учебных часов;
- считать завершённый курс доказательством обучения;
- утверждать, что один опрос установил точную причину любой проблемы;
- заменять медицинскую или психологическую помощь.

Результат представляет собой рабочую модель, в основном построенную на
самоотчёте. Рекомендации нужно проверять по реальному поведению и обновлять,
когда появляются новые данные.

## Приватность

Для работы не нужно передавать исходный код, пароли, API keys, данные клиентов,
названия компаний или конфиденциальную архитектуру.

Используйте обезличенные описания. Например:

```text
Я поддерживаю большой event-driven сервис с медленными integration tests.
```

вместо proprietary-кода или внутренней документации.

## Научная основа и границы выводов

Coach разделяет:

- факты, сообщённые пользователем;
- выводы из ответов;
- общие положения, подтверждённые исследованиями обучения;
- практические гипотезы, которые ещё нужно проверить.

Исходные источники и ограничения описаны в
[`evidence-base.md`](skills/developer-learning-coach/references/evidence-base.md).
Toolkit не использует неподтверждённые learning-style labels и не предполагает,
что результаты образовательных экспериментов автоматически переносятся на
профессиональную разработку ПО.

Исходные frontend-сценарии и примеры учебных программ сохранены в каталоге
[`drafts/`](drafts/) как материал для будущего адаптера. Generic skills их не
загружают, поэтому они не влияют на планы для других специальностей.

## Безопасность

Plugin не содержит MCP-сервера, hooks, analytics или удалённого хранилища.
Локальный Python-рендерер читает roadmap JSON и создаёт автономный HTML без
сетевых запросов. Ответы обрабатываются платформой, в которой запущен диалог;
применяются её правила приватности и хранения данных.

Текущая модель угроз и требования к будущим расширениям описаны в
[`SECURITY.md`](SECURITY.md).

## Текущий статус

Это ранняя версия plugin. Все четыре skill остаются самостоятельными и не
требуют внешних сервисов.

Особенно полезна обратная связь со следующими данными:

- использованный запрос;
- активировавшийся skill;
- неясные или повторяющиеся вопросы;
- связь итоговых рекомендаций с ответами;
- изменения после одной или двух недель практики.

Не публикуйте реальные ответы, если они содержат личные или рабочие данные.
